# 📄 Project Brief: "DevSecOps Sentinel AI"

**Date:** September 22, 2026
**Client:** Engineering & Cybersecurity Direction (VP of Engineering & CISO)
**Prepared for:** Product Owner / Lead Developer

---

## 1. Product Vision & Business Problem

Engineering teams currently spend countless hours reviewing Pull Requests manually or dealing with traditional static code analyzers (like SonarQube or ESLint). These legacy tools often generate hundreds of false positives, lack contextual understanding of code intent, run slowly, and fail to provide real-time feedback during execution.

**DevSecOps Sentinel AI** is designed as a unified command center that enables organizations to audit code repositories using an **autonomous AI agent**. The platform detects security vulnerabilities (OWASP Top 10) and code smells, streams step-by-step execution logs in real time, and delivers ready-to-apply code refactorings.

---

## 2. Core Objectives (Success KPIs)

1. **Real-Time Observability:** Eliminate developer friction during audits by streaming the agent's thought process and actions live (log latency < 500ms).
2. **Strict Architectural Modularization:** The user interface must adopt a **Microfrontend (MFE)** architecture, enabling distinct frontend teams to independently evolve the Configuration module and the Metrics/Analytics module.
3. **Actionable Fixes over Noise:** Rather than simply listing issues, the agent must provide an **AI-generated refactored code snippet** ready for copy/apply.

---

## 3. Project Scope (MVP)

The Minimum Viable Product (MVP) to be delivered within a 15-day timeframe consists of three primary functional modules:

### A. MFE 1: Audit Configuration (`mfe-config`)
* Repository selection (Git URL or local test repository).
* Rule set customization:
  * Security Vulnerabilities (OWASP Top 10).
  * Unit Test Quality & Coverage.
  * Code Smells & Performance.
* Severity threshold filter (*Low, Medium, High, Critical*).
* Audit launch button (`POST /api/v1/audits`).

### B. MFE 2: Live Console & Metrics Dashboard (`mfe-metrics`)
* **Live Agent Console (SSE):** Streaming event feed generated by the agent (*"Cloning repo"*, *"Analyzing auth.ts"*, *"Vulnerability found"*).
* **Health Dashboard:** Interactive visual summary of project health (Severity distribution chart, Overall Health Score from 0 to 100).
* **Refactoring Drawer:** Interactive issue list displaying side-by-side code comparisons (*Before / After refactored by AI*).
* Export functionality for final reports in **Markdown** format.

### C. Agent Engine & Specification (SDD)
* Upfront specification of all contracts in `/specs` (`openapi.yaml` for REST endpoints, `events-schema.json` for SSE events).
* Executor Agent service leveraging LLM APIs to inspect code snippets against specified contracts.

---

## 4. Technical Stack & Constraints

* **Frontend Architecture:** React + Vite + Module Federation (`mfe-shell`, `mfe-config`, `mfe-metrics`).
* **Quality & Testing (Mandatory):**
  * Unit/Integration test coverage > 80% using **Vitest** and **React Testing Library**.
  * At least 1 End-to-End (E2E) test suite using **Playwright** covering the complete flow from `mfe-config` to `mfe-metrics`.
* **API Communication:** Server-Sent Events (SSE) for real-time agent activity streaming.
* **Budget:** $0 (Free-tier LLM APIs, Ollama local models, or internal free CLI tools).

---

## 5. SDD Acceptance Criteria

Before writing application source code, the following specification deliverables must be validated:

1. A valid `specs/openapi.yaml` contract defining audit creation endpoints.
2. A valid `specs/events-schema.json` contract defining the 4 core SSE event types emitted by the agent: `AGENT_THOUGHT`, `TOOL_EXECUTION`, `VULNERABILITY_FOUND`, and `AUDIT_COMPLETED`.
3. An `ARCHITECTURE.md` file featuring a Mermaid diagram illustrating the communication between the `Shell` host and the two remote MFEs.
